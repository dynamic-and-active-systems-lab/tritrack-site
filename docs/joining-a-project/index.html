Joining a project

A project belongs to whoever created it. To get onto somebody else’s project you ask for a place on it with a short code, and one of that project’s owners decides. Nobody joins by holding the code alone.

You need a connection for this part

Joining is the one thing in TriTrack that cannot be done in the field. Everything else — recording bearings, reading the map, working through a whole day out of signal — works with no connection at all. Asking to join, and the approval coming back, both need the phone to reach the server.

Do it before you leave, in the truck at the trailhead, or anywhere with a bar of signal. The app says as much if you try without one.

First: point the phone at a server and sign in

Before any of this there has to be a server and this device has to be signed in to it. Open More , then Server Connection , and put in the address whoever runs your project server gave you.

Then REQUEST A SIGN-IN CODE , with your email address. A code is issued and you paste it into Sign-in code below — or paste the whole link, which works too.

How that code reaches you depends on the server, and the app cannot tell you. Some setups email it; some hand it to you another way entirely. The server answers the app identically whichever it does, deliberately — so a screen promising you an email would be a promise the app is in no position to make. If nothing arrives, ask whoever set the server up how codes are delivered there. That is a real question with a real answer, and it is theirs rather than the app’s.

Signing in is per device. A second phone signs in the same way with the same address and the same email.

If you own the project: turn joining on and hand out the code

Open More , then Projects , then the three-dot button at the end of your project’s row, and choose Members .

The screen opens on a card naming your own role, which is there for everybody rather than for owners — see projects, members and roles. Scroll past it for the member list, the join code and, further down, anybody waiting.

Turn on Let people join with a code and the code appears under it. Give it to your crew however suits you — the app does not send it anywhere, and it does not expire. The same code works for everybody.

New code replaces it. Do that when somebody leaves the crew and you would rather the old code stopped working; anybody who has already joined stays on the project, and anybody still waiting for you to decide is cleared out and has to ask again with the new code.

Team size limit caps how many people can be on the project. People waiting for approval take up a place too, so a project sitting at its limit with requests outstanding will refuse the next person.

If you are joining: ask with the code

Open More , then Projects , then the row headed Join a project — it sits above the list, and it is there when the list is empty too, which is where somebody who has just been handed a code is usually looking.

Type the code into Join code . Your name is already filled in from your profile — change it if the owner knows you by something else. Then tap Ask to join .

The owner sees two things about you: the email address you signed in with, which the server vouches for, and the name you typed, which it labels as something you said about yourself. If they do not recognise the address, the name is what makes approval a judgement rather than a guess.

Asking is not joining

Nothing reaches your device at this point. The screen says Waiting for approval and the same request appears under Your requests , both here and on your projects list — so you do not have to keep this screen open, and you do not have to come back to it.

What the owner is asked

An owner opening the Members screen sees you under Waiting to join , with your address, your name and the date you asked.

Tapping Approve does not let you in on its own — it opens this:

Two things are decided here, and the button stays greyed out until the second one is done.

The role. It starts at Contributor — records their own , which is the ordinary case for a field tech. The other two are Viewer — read only and Owner — also manages members . What each one can do is on the projects, members and roles page.

The sentence about removal. It says that removing somebody later stops their app syncing and blocks them from the server, but cannot delete the project data already downloaded onto their device. That is true and it is worth reading before you tick it, especially for a project on a species where a precise location is itself sensitive. Only let in people you are willing to trust with the locations they will take away with them.

Reject turns the request down instead. The person is told, and can ask again with the same code.

When the answer comes back

Once an owner approves, the project downloads by itself. You do not go back to the join screen and you do not tap anything.

How long it takes to notice depends on what the phone is doing, and these are the numbers:

  • The app is open. Up to about a minute. It checks every 60 seconds while you have a request outstanding.
  • The app is in the background. It checks the moment you bring it back to the front. In practice that is as fast as watching the screen, because you look at the phone before the phone looks for you.
  • The app is fully closed. Nothing happens at all until you open it, and then it checks straight away.

That last one is expected behaviour rather than something being stuck. TriTrack has no way to reach a closed app — there are no push notifications — so a phone sitting in a pack overnight learns nothing overnight. Open the app and the answer is there within a second or two.

If you would rather not wait for the next check, pull down on the projects list. That asks immediately.

When it does not work

The owner turned it down. You are told, on the same card in the same place — not left waiting. You can ask again with the same code.

The code stopped working. If an owner made a new code while your request was outstanding, your request is cleared and the card says so. Ask them for the new code.

You are in, but nothing downloaded. The approval reached you and the project did not. The card tells you which of the two situations you are in: the project is in your list but part of its history is still to come, or it has not started arriving at all. Either way it finishes itself the next time you open the app somewhere with a connection. Nothing is lost and nothing needs re-asking.

Nothing at all is happening. Check that the app is open, that you have signal, and pull down on the projects list. If it still says nothing, the likeliest answer is that the owner has not looked at their phone yet.
