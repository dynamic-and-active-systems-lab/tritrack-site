Support

This page is mostly not written yet. It will carry the ways to report a problem or ask a question, and what the app is and is not expected to do without a network connection. One part of it is written, because it is the part that makes every report usable.

Which version are you on?

Open More and choose App Info . The first line is the version and the build number, and it is selectable — long-press to copy it and paste it into your report.

Please include it. There are several builds of TriTrack in circulation on different platforms at any time, and a report that cannot be tied to one gets read against the wrong version of the app. The screen reads the number out of the installed build rather than from anything typed into the source, so it is the version you are actually holding.

If it says it could not read the version, say how you installed the app and roughly when, instead.

The rest of the screen is the full credit and licence text for the map imagery, which is why the credit line on the map itself can be short.

Getting in touch

TriTrack is developed in the Dynamic and Active Systems Lab at Northern Arizona University.

This site is published from github.com/dynamic-and-active-systems-lab/tritrack-site, and that repository is the route to whoever maintains it — for a bug report, a question about the app, or a query from a map tile provider about the requests this app makes.

That last one is why this section exists rather than waiting for the rest of the page. The app identifies itself to map tile services with the address of this site, so that anybody serving those tiles has a way to reach a person. A published contact that cannot be contacted would be worse than none.
